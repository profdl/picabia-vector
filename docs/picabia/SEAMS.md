# Picabia seams in upstream VectorCraft files

Every edit Picabia makes to a file that comes from upstream VectorCraft is a *seam*: as few lines as
possible, calling into Picabia code, marked `// PICABIA: <reason>` (`rg "PICABIA:"` lists them).
When an upstream merge conflicts, resolve it seam by seam with this table, then run `cargo xtask ci`.

| File | Function / item | Why | How to re-apply |
|---|---|---|---|
| `.github/workflows/release.yml` (`release` job), `sonarcloud.yml`, `freebsd.yml`, `windows-arm64.yml` | top job | Need storytold signing secrets, SonarCloud token or its runners/schedules | Re-add `if: github.repository == 'storytold/vectorcraft'` under the job name (4 lines in all). `ci.yml`, `nix.yml`, `packaging-lint.yml`, `affinity-corpus.yml` and `print.yml` run unchanged on GitHub-hosted runners. |
| `Cargo.toml` | `[workspace.dependencies]` | Picabia crates are workspace dependencies | One `vectorcraft-<crate> = { path = "crates/<crate>" }` line per Picabia crate under a `# PICABIA:` comment (`vectorcraft-modifiers`; `vectorcraft-stencil`; `vectorcraft-grbl`, the GRBL laser link, whose native-only `serialport` dependency is declared in `crates/grbl/Cargo.toml`, so `Cargo.lock` gains serialport and its platform dependencies). Workspace members come from the `crates/*` glob. |
| `xtask/src/layers.rs` | `TABLE` | `cargo xtask layers` must know each Picabia crate's layer | One row per Picabia crate under a `// PICABIA:` comment: `("modifiers", Class::Layer(2))`, `("stencil", Class::Layer(3))`, `("grbl", Class::Standalone)` (no workspace deps; the engine may depend on it). |
| `crates/engine/src/cmd.rs` | `ordinary_isolation` | clippy 1.96 flags upstream's boolean (`nonminimal_bool`); `cargo xtask ci` fails on pristine upstream | `#[allow(clippy::nonminimal_bool)]` on the function. Drop it once upstream rewrites the expression. |
| `crates/engine/Cargo.toml` | `[dependencies]` | The `modifier.*` commands read and write stacks with `vectorcraft-modifiers` | Re-add `vectorcraft-modifiers = { workspace = true }` under a `# PICABIA:` comment. |
| `crates/engine/src/cmd.rs` | module list; `command_specs` | Register the `modifier.*` commands (code in `cmd/picabia_modifier.rs` and its folder); the module is `pub` so the panel can call `target_choices`/`check_target` | Re-add `pub mod picabia_modifier;` after `pub mod perspgrid;` and `v.extend(picabia_modifier::specs());` at the end of the `command_specs` list (both marked `// PICABIA:`). |
| `crates/engine/src/lib.rs`, `crates/engine/src/session/documents.rs` | `Session` (last field); `Session::new` | Picabia's session state in one field (`modifier.copy` keeps its rows there for `modifier.paste`, apart from the objects' clipboard, so copying objects keeps them) | Re-add the field `pub(crate) picabia: cmd::picabia_modifier::PicabiaState,` and its initializer `picabia: Default::default(),` (both marked `PICABIA:`). |
| `crates/engine/src/cmd/edit.rs` | `paste_clip` (in the edit closure, after the paste loop, before `sel.set`); `copy_above` (before `refresh_bounds_of`) | Copy-to-shape targets (object ids inside the `picabia.modifiers` attribute) copied together with their source point at the copies: paste (`remap_pasted`, one map per placement; from another document targets left behind are cleared) and every `copy_above` caller: duplicate, copying moves/transforms (Alt-drag), Transform Again, perspective copies, layer duplicate, artboard copy-with-art (`remap_copies`). The adapter walks original and copy side by side; `Document::reid` is untouched | Re-add `super::picabia_modifier::remap_pasted(d, &clip.nodes, &new_ids, same_doc);` and `super::picabia_modifier::remap_copies(d, roots, &out);` (both marked `// PICABIA:`) |
| `NOTICE` | Third-party material (after the Rust dependency licence paragraph) | The laser link (`vectorcraft-grbl`, native only) uses `serialport`, MPL-2.0, unmodified: the only dependency outside the permissive licences listed there (plus `unescaper`, used under MIT) | Keep the "PICABIA: the desktop app's laser link uses the serialport crate" paragraph after the Rust dependencies paragraph |
| `crates/render/Cargo.toml`, `crates/render/src/lib.rs` | `[dependencies]`; module list | The renderer draws modifier copies (`src/picabia.rs`) | Re-add `vectorcraft-modifiers = { workspace = true }` under a `# PICABIA:` comment and `pub mod picabia;` before `pub mod placed_document;`. |
| `crates/render/src/fx/predicates.rs` | `has_object_fx` | An object with an active stack draws through its art, as Crop Marks and Vector Halftone do | Re-add `\|\| crate::picabia::has_stack(n)` as the last term. |
| `crates/render/src/fx/renderer.rs` | `fx_art` (first line; head of the art chain); `draw_object_fx_art` (`rfx`); `fx_art` (`outer` colour map) | The art is the group of copies, each drawing the object's own effects: no raster effects or colour adjustments around it a second time; copy-to-shape art isn't kept by the source's identity (it follows the target) | Re-add `let cache = cache && !crate::picabia::has_targets(a);` as the first line of `fx_art`; `crate::picabia::art_node(doc, a)` as the first link of the `match` chain (before `crop_marks_art`); `\|\| crate::picabia::has_stack(a)` in the `rfx` and `outer` conditions next to `has_halftone(a)`. |
| `crates/render/src/renderer/nodes.rs` | `bounds_of` (cache hit); `draw_arc_body` (plain path fast path) | Copy-to-shape bounds follow the target; a stacked plain path must not take the fast path (it would draw once) | Re-add `&& !crate::picabia::has_targets(a)` to the cache-hit condition and `&& !crate::picabia::has_stack(a)` after `!fx::has_fx(a)` in the fast path. |
| `crates/render/src/fx/bounds.rs` | `cull_bounds_in` (before the `match`) | Bounds, culling, dirty regions and export crops cover every copy | Re-add `if let Some(art) = crate::picabia::art(symbols.document(), n) { return inner(&art); }`. |
| `crates/render/src/changed.rs` | `changed` (after `diff.children`) | A copy-to-shape source whose target moved repaints although the source itself didn't change | Re-add `diff.area = vectorcraft_geom::union_opt(diff.area, crate::picabia::dependents(old, new));`. |
